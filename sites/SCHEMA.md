# Site profile schema

Generated by `python3 -m buffon site schema`; do not edit. A profile is a TOML file; every key is optional unless the table says otherwise.

## `[site]`

| key | type | default | meaning |
|---|---|---|---|
| `name` | str | (file name) | Name printed in every report. |
| `backend` | str | local | Execution backend: `local` or `kubernetes`. |
| `hardware` | str | shared | What you claim about the machine: `dedicated` (nothing else runs on these cores) or `shared`. A claim never upgrades a run on its own: the runner also detects quietness (governor, load, contention on the pinned cores), and a run is labelled quiet dedicated hardware only when claim and detection agree. |
| `notes` | str |  | Free text copied into the report. |

## `[local]`

| key | type | default | meaning |
|---|---|---|---|
| `cpus` | cpus | (none) | CPUs the harness processes are pinned to, as a list such as `8-11` or `2,4,6`. Required when `pinning = "required"`. |
| `mock_cpus` | cpus | (none) | CPUs the runner and the mock endpoint are pinned to. Must not overlap `cpus`. When empty the runner is not pinned. |
| `pinning` | str | preferred | `required`: refuse to run when the harness cannot be pinned; `preferred`: pin when `cpus` is set, otherwise run unpinned and label the run PROVISIONAL; `none`: never pin (labelled PROVISIONAL). |
| `cache_dir` | str | $XDG_CACHE_HOME/buffon | Where verified artifact downloads are kept. The runner re-verifies each file's sha256 before use. |
| `work_dir` | str | $TMPDIR | Parent of the throwaway directory each run installs arms into. |
| `lock_files` | list-str | (none) | Lock files other benchmark tools on this host hold (for example a host bench slot). The run refuses to start while one is held by someone else; a run inside the holder's wrapper is let through. Buffon also takes its own exclusive lock, so one Buffon measurement runs per host (with `slots`, each slot has its own lock and the host-wide one is held shared). |
| `slots` | int | 1 | Opt-in: run this many measured sessions at once on disjoint core sets of this host (`buffon campaign` only; docs/METHODOLOGY.md, "Slots on one big host"). `1` is one session at a time, as before. With 2 or more, `cpus` and `mock_cpus` give the size of one slot (how many harness CPUs and mock CPUs a session gets, not which ones); the runner splits the CPUs it may use into that many slots of whole physical cores, one NUMA node each where the host allows, and refuses a split that would share a core. Needs a local site with `cpus` and `mock_cpus`, on Linux. |
| `quiet_max_busy` | float | 0.10 | Before every sample the pinned CPUs must be at most this busy (a fraction); otherwise the runner waits and records the wait. |
| `quiet_timeout_s` | float | 300 | How long the runner waits for a quiet host before a sample; after that the sample fails with the readings recorded. |
| `quiet_max_runnable` | nonneg-int | 0 | The most other runnable threads allowed on the pinned CPUs before a sample (0: none). Only the pinned CPUs count; the load of the rest of the host is recorded but never gated on. |
| `quiet_max_steal` | float | 0.02 | Before every sample no pinned CPU may lose more than this share of its time to the hypervisor (steal). |
| `quiet_max_psi` | float | 10 | Before every sample the CPU pressure (some, avg10, percent) of the runner's cgroup, or of the system when the cgroup has no pressure file, must be at most this. A cgroup that was CPU-throttled during the check also fails it. |
| `host_claim` | str | B | `A`: the site declares this host dedicated (nothing else is scheduled on the benchmark's CPUs); preflight checks the claim and downgrades the run to class B when it does not hold. `B`: shared host, results PROVISIONAL. |
| `require_class` | str | (none) | `A` or `B`: refuse to run on a host of a lower class (A = dedicated and publishable). |
| `clock_claim` | str | (none) | `hypervisor`: this machine is a virtual machine whose platform fixes the CPU clock and turbo state and shows no cpufreq or turbo interface, so the runner cannot read them. The site says so; the runner does not verify the clock, and it honours the claim only on a machine that shows it is a virtual machine (the CPU's hypervisor flag, or systemd-detect-virt naming one); elsewhere the run records `clock_claim_refused`. With it, an unreadable clock and turbo state no longer keep a run out of class A, the report states the claim, and a governor that is readable and scales the clock still does. |
| `meter` | str | auto | Resource meter: `auto`, `cgroup-direct`, `cgroup-systemd` or `rusage`. |
| `allow_frequency_scaling` | bool | false | Run although a pinned CPU's governor scales its clock. The run is then labelled PROVISIONAL. |

## `[kubernetes]`

| key | type | default | meaning |
|---|---|---|---|
| `kubeconfig` | str |  | Path of the kubeconfig. Empty uses $KUBECONFIG or kubectl's default. |
| `context` | str |  | kubectl context. Empty uses the current context. |
| `namespace` | str | (required) | Namespace in which the runner creates Jobs and reads pods and logs. |
| `image` | image | (required unless bundle) | Benchmark image, pinned by digest: `<registry>/<repository>@sha256:<64 hex>`. A tag is refused. |
| `bundle` | bool | false | Run the pinned `base_image` and copy the repository and the verified artifact cache into it with `kubectl cp` (see docs/RUNNING.md), instead of pulling `image`. |
| `base_image` | image |  | Digest-pinned image a bundle runs on. It needs Python 3.11 or later and the prerequisites listed in docs/RUNNING.md. |
| `arch` | str | amd64 | Architecture of the nodes, `amd64` or `arm64`. `buffon run` builds the bundle for it; a bundle pod on a node of another architecture refuses to start. |
| `cpus` | int | 2 | Whole CPUs for the pod. Requests equal limits, so the pod has Guaranteed QoS and a static CPU manager gives it exclusive cores. |
| `memory` | quantity | 8Gi | Memory request and limit. |
| `scratch_size` | quantity | 8Gi | Size limit of the scratch volume the session writes to. |
| `node_selector` | table | {} | Labels of the dedicated node pool. |
| `tolerations` | list-table | [] | Tolerations for the pool's taints. |
| `node` | str |  | Pin the pod to one node by name. |
| `nodes` | list-str | [] | Run the same session on each of these nodes at once (one pod each), or, with `spread`, the nodes it picks from. Excludes `node`. |
| `spread` | nonneg-int | 0 | Run the same session at once on this many nodes, the ones with the most free CPU (of `nodes` when given). 0: one node. Excludes `node`. |
| `image_pull_secrets` | list-str | [] | Names of image pull secrets. |
| `service_account` | str |  | Service account of the pod. |
| `deadline_seconds` | int | 21600 | Job deadline. |
| `ttl_seconds` | int | 604800 | How long the cluster keeps a finished Job. |
| `pin` | str | auto | CPUs inside the pod the processes are pinned to: `auto` (the quietest of the allowed cores), `none`, or a list. |
| `allow_frequency_scaling` | bool | false | Run on a node whose measured cores scale their clock. The run is reported but labelled PROVISIONAL. |
| `secret_env` | list-table | [] | Environment variables the pod reads from Kubernetes Secrets in `namespace`, each `{ name = "<VARIABLE>", secret = "<secret name>", key = "<key in the secret>" }`. Only the reference reaches the pod spec: a secret value never passes through the profile, the session or the runner, and an entry with any other key is refused. |
| `max_cv` | float | 0.05 | Cross-node calibration gate: the largest coefficient of variation a gated metric may have (between 0 and 1). A calibration over the nodes refuses a comparison above it. |

Environment overrides: `BUFFON_SITE`, `BUFFON_CPUS`, `BUFFON_MOCK_CPUS`, `BUFFON_CACHE_DIR`, `BUFFON_WORK_DIR`, and `BUFFON_K8S_<KEY>` for every `[kubernetes]` key (for example `BUFFON_K8S_NAMESPACE`, `BUFFON_K8S_IMAGE`). A list or table override is JSON, for example `BUFFON_K8S_NODE_SELECTOR='{"pool": "bench"}'`; an override is checked like a profile value.
